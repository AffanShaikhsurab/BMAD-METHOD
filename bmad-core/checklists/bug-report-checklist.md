# Bug Report Checklist

Use this checklist to ensure comprehensive bug reports that enable efficient debugging and resolution.

## Essential Information

### Issue Description
- [ ] **Clear, concise title** that summarizes the problem
- [ ] **Detailed description** of what went wrong
- [ ] **Impact assessment** - who/what is affected
- [ ] **Severity level** (Critical/High/Medium/Low)

### Reproduction Details
- [ ] **Steps to reproduce** the issue (numbered list)
- [ ] **Expected behavior** - what should happen
- [ ] **Actual behavior** - what actually happens
- [ ] **Frequency** - does it happen every time or intermittently?
- [ ] **First occurrence** - when was this first noticed?

### Environment Information
- [ ] **Operating System** and version
- [ ] **Browser/Application** version (if applicable)
- [ ] **Environment** (development/staging/production)
- [ ] **Device type** (desktop/mobile/tablet)
- [ ] **Screen resolution** (for UI issues)

### Technical Details
- [ ] **Error messages** (exact text, screenshots, or logs)
- [ ] **Stack traces** (if available)
- [ ] **Console errors** (browser developer tools)
- [ ] **Network requests** that failed (if applicable)
- [ ] **Database queries** involved (if known)

### Code Context
- [ ] **Affected files** or modules
- [ ] **Recent changes** that might be related
- [ ] **Git commit hash** of current version
- [ ] **Branch name** where issue occurs
- [ ] **Related pull requests** or issues

### Supporting Evidence
- [ ] **Screenshots** or screen recordings
- [ ] **Log files** (application, server, database)
- [ ] **Configuration files** (if relevant)
- [ ] **Sample data** that triggers the issue
- [ ] **Test cases** that demonstrate the problem

### Workarounds
- [ ] **Temporary solutions** (if any exist)
- [ ] **Alternative approaches** that work
- [ ] **Blocking factors** - what can't be done because of this bug

### Additional Context
- [ ] **User story** or feature this relates to
- [ ] **Business impact** - how does this affect users/business
- [ ] **Timeline** - when does this need to be fixed
- [ ] **Related issues** or dependencies
- [ ] **Contact information** for follow-up questions

## Quality Checks

- [ ] **Reproducible** - can someone else follow your steps and see the same issue?
- [ ] **Specific** - is the description clear and unambiguous?
- [ ] **Complete** - have you provided all necessary information?
- [ ] **Actionable** - can a developer start working on this immediately?

## Submission Guidelines

1. **Search existing issues** first to avoid duplicates
2. **Use appropriate labels** (bug, severity, component)
3. **Assign to correct team** or component owner
4. **Set priority** based on impact and urgency
5. **Follow up** if more information is requested

---

*This checklist ensures that bug reports contain all information needed for efficient diagnosis and resolution. Complete as many items as possible to help the repair agent and development team quickly understand and fix the issue.*
